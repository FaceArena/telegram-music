# 🎵 Music Telegram Bot

Пишешь название трека (или ссылку на YouTube) → бот присылает mp3.
Работает в личке и в группах. Стек: Python, python-telegram-bot, yt-dlp, FFmpeg.

## Локальный запуск через `.env`

1. Скопируй `.env.example` в файл `.env`.
2. Открой `.env` и укажи токен:
   `BOT_TOKEN=твой_токен_от_BotFather`
3. Установи зависимости: `pip install -r requirements.txt`.
4. Запусти: `python main.py`.

Для запуска в Docker: скопируй `.env.example` в `.env`, заполни `BOT_TOKEN` и выполни `docker compose up --build -d`. Остановка: `docker compose down`.

Приложение автоматически прочитает `.env`. Этот файл игнорируется Git и не попадёт в репозиторий. Для Railway не загружай `.env`: добавь `BOT_TOKEN` в Variables сервиса.

## 1. Токен у @BotFather
1. В Telegram открой @BotFather → `/newbot`.
2. Задай имя и username (оканчивается на `bot`).
3. Скопируй токен вида `123456:ABC...` — это `BOT_TOKEN`.

## 2. Работа в группах (отключить Privacy Mode)
@BotFather → `/mybots` → твой бот → **Bot Settings** → **Group Privacy** → **Turn off**.
После этого **удали бота из группы и добавь заново** — иначе настройка не применится.
В личном чате просто отправь название песни. В группе упомяни бота: `@бот название песни`.
Чтобы он отвечал на любое короткое сообщение (до 120 символов), задай `GROUP_REACT_ALL=1`.

## 3. Cookies YouTube (против «Sign in to confirm you're not a bot»)
IP облачных серверов YouTube часто блокирует. Cookies — самая надёжная защита. Без них бот тоже работает, но может периодически получать блокировку.

Важно:
- Используй **отдельный (запасной) аккаунт Google**, не основной: yt-dlp-активность с аккаунта может привести к его ограничению.
- Cookies = доступ к аккаунту. Никому не показывай и не клади в репозиторий.

Как получить (рабочий способ):
1. Открой **приватное окно** (в Safari: вкладки → Приватный доступ).
2. Войди в YouTube запасным аккаунтом.
3. В **этой же вкладке** открой `https://www.youtube.com/robots.txt` (так cookies не «прокрутятся» страницей).
4. Экспортируй cookies в формате **Netscape cookies.txt** расширением браузера (например, «Get cookies.txt LOCALLY» в Chrome/Firefox на компьютере; для Safari на iPhone/iPad подойдёт любое Safari-расширение, умеющее экспорт в Netscape-формат). Экспортируй только домен `youtube.com`.
5. Сразу закрой приватное окно (не выходи из аккаунта вручную — это обнулит cookies).

Перевод в base64:
- **iPhone:** приложение «Быстрые команды» → действие «Закодировать (Base64)» по файлу → скопировать результат.
- **Компьютер:** `base64 -w0 cookies.txt` (macOS: `base64 -i cookies.txt`).
- Не используй онлайн-конвертеры — cookies секретны.

Результат вставь в переменную `YOUTUBE_COOKIES_B64`.

## 4. Деплой через браузер
1. Зарегистрируйся на GitHub, нажми **New repository** (private), загрузи туда все файлы этой папки: **Add file → Upload files**.
> ⚠️ **Render worker — платный (starter, от $7/мес).** Для бесплатного запуска используй Railway (стартовый кредит) или другой хостинг. `render.yaml` оставлен как опция для тех, кто готов платить.

2. **Railway:** railway.com → New Project → Deploy from GitHub repo → выбери репозиторий. Railway сам найдёт Dockerfile.
   **Render:** render.com → New → Background Worker → подключи репозиторий, Runtime = Docker (или New → Blueprint по `render.yaml`).
3. Во вкладке **Variables** (Railway) / **Environment** (Render) добавь:
   - `BOT_TOKEN` — обязательно
   - `YOUTUBE_COOKIES_B64` — рекомендуется
4. Деплой запустится сам. В логах должна появиться строка `yt-dlp ..., стратегий: N`.

Бот — это worker (не веб-сервис), порт открывать не нужно.

## 5. Как устроена защита от блокировок
Бот пробует короткую цепочку стратегий без промежуточных сообщений в чате:
Если `MWEB_FIRST=1` (по умолчанию), первой пробуется стратегия с клиентом `mweb`. Затем при наличии cookies используются настроенные `YT_CLIENTS` (по умолчанию `tv,web_embedded`), после них `web` с cookies и `web` без cookies. Без cookies остаются `mweb`, настроенные клиенты и `web`. PO Token подключается автоматически, если задан `POT_PROVIDER_URL`.

Также: yt-dlp обновляется каждые 12 часов (с перезапуском). Искусственная пауза между скачиваниями по умолчанию отключена; её можно включить через `MIN_DELAY` и `MAX_DELAY`. Одновременно выполняется не более `MAX_PARALLEL_DL` загрузок (по умолчанию 3). Используется короткая цепочка целевых стратегий; сетевые таймауты и повторы сокращены. Клиент `android` не используется.

Для защиты от пиков нагрузки по умолчанию обрабатывается не более 32 обновлений одновременно, очередь входящих обновлений ограничена 128 элементами (`MAX_CONCURRENT_UPDATES`, `MAX_PENDING_UPDATES`). Одновременно выполняется до 3 загрузок, до 5 отправок аудио в Telegram и до 2 распознаваний видео (`MAX_PARALLEL_DL`, `MAX_PARALLEL_SEND`, `MAX_PARALLEL_VIDEO`). Если лимит распознавания видео занят, бот попросит повторить запрос позже. Эти лимиты действуют внутри одного процесса; они не являются общей координацией между несколькими экземплярами и не подтверждают поддержку 1000 одновременных пользователей.

Каждую минуту в логах появляется строка `RUNTIME_METRICS`: размер очереди, активные обработчики, p95/p99 задержек, ожидание лимитов, cache hit rate, ошибки YouTube/AudD/FFmpeg/Telegram, число `RetryAfter`, CPU time, пиковая RSS-память и свободное место на диске. Метрики хранят последние 200 замеров в памяти и не требуют внешнего сервиса.\n\nВ тестах есть синтетический сценарий на 1000 фальшивых updates. Он проверяет backpressure и локальные лимиты без обращения к Telegram/YouTube/AudD; это не live-нагрузочный тест и не подтверждение 1000 реальных пользователей.

## 6. План, если cookies не помогли
1. **Обнови cookies**: они «протухают». Повтори шаг 3 заново (приватное окно, robots.txt, экспорт).
2. **PO Token Provider (рекомендуется):**
   - Railway: в том же проекте **New → Docker Image** → `brainicism/bgutil-ytdlp-pot-provider`.
   - В сервисе бота добавь `POT_PROVIDER_URL=http://<имя-сервиса>.railway.internal:4416` (имя смотри в настройках Networking нового сервиса).
   - Render: создай отдельный Private Service из того же образа и укажи его внутренний адрес.
   - Плагин `bgutil-ytdlp-pot-provider` уже в `requirements.txt`.
3. **Смена клиентов:** задай переменную `YT_CLIENTS` (по умолчанию `tv,web_embedded`). Укажи нужные клиенты через запятую, например `tv,web_embedded`. Изменение применяется после перезапуска бота.
4. **Смена региона/хостинга:** IP некоторых регионов блокируется сильнее. В Railway/Render выбери другой регион, либо перенеси на VPS.
5. Проверь логи: строка `Стратегия «...» не сработала: ...` покажет точную причину.

## Распознавание музыки из видео

Отправь боту обычное видео, видеозаметку или видеофайл (MP4/MOV/MKV/AVI/WebM). Бот скачает его, извлечёт первые 20 секунд звука через FFmpeg, отправит аудиофрагмент в стандартный AudD API, найдёт полную версию по исполнителю и названию и отправит MP3. Само видео в AudD не загружается: стандартный endpoint принимает аудио до 10 МБ. Размер исходного видео ограничен 20 МБ из-за стандартного Telegram Bot API.

Чтобы включить функцию:
1. Получи API-токен на https://dashboard.audd.io (новым аккаунтам может быть доступен пробный лимит 300 запросов на 14 дней).
2. Добавь в Variables Railway переменную `AUDD_API_TOKEN` с этим токеном и перезапусти сервис.

Каждое распознавание использует один запрос стандартного AudD API. Без `AUDD_API_TOKEN` обычный поиск по названию и скачивание продолжают работать как раньше; распознавание видео будет отключено. Если музыка начинается не сразу, распознавание может не найти её в первом фрагменте.

## Переменные окружения
| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота | — (обязательна) |
| `AUDD_API_TOKEN` | токен AudD для распознавания музыки в присланных видео | пусто (функция видео отключена без токена) |
| `YOUTUBE_COOKIES_B64` | cookies.txt в base64 | пусто |
| `YOUTUBE_COOKIES_FILE` | путь к cookies.txt | пусто |
| `POT_PROVIDER_URL` | адрес bgutil-провайдера | пусто |
| `MAX_DURATION` | макс. длительность, сек. Файлы больше примерно 49 МБ бот не отправляет и сообщает об ошибке. Для mp3 128 kbps это примерно 50 минут, так что при 1200 (20 мин) лимит не будет превышен | 1200 |
| `MIN_DELAY` / `MAX_DELAY` | пауза между скачиваниями, сек | 0 / 0 |
| `AUDIO_QUALITY` | битрейт mp3, kbps | 128 |
| `MAX_PARALLEL_DL` | максимум одновременных скачиваний | 3 |
| `YT_CLIENTS` | список клиентов YouTube для yt-dlp | `tv,web_embedded` |
| `AUDIO_FORMAT` | `mp3` или `m4a` (без перекодирования, быстрее) | mp3 |
| `CACHE_DIR` | папка SQLite-кэша (`file_id` треков и поиск). Если подключён том — укажите его путь; по умолчанию `/data`, если есть, иначе временная папка (кэш сбрасывается при деплое) | /data |
| `SEARCH_CACHE_TTL` | время жизни кэша поиска, сек. | 21600 |
| `PREFETCH_TOP` | сколько первых результатов поиска готовить заранее (0 — выключить) | 1 |
| `MWEB_FIRST` | первой стратегией пробовать mweb без ожидания рекламы (не использовать с cookies Premium) | 1 |
| `GROUP_REACT_ALL` | По умолчанию 0 — бот реагирует только на упоминания и команды. Установи 1, если хочешь, чтобы бот отвечал на любое короткое сообщение в группе | 0 |
| `UPDATE_EVERY_HOURS` | период обновления yt-dlp | 12 |

Используй бота для личных целей и с уважением к авторским правам и правилам YouTube.
